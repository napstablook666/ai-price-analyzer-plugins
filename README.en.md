# AI Price Analyzer Plugin Repository

This repository is the single hand-written source of site plugins for AI relay stations. One station per directory; the extension repository generates the runtime plugins and the site catalog from these sources.

- Extension repository: <https://github.com/napstablook666/ai-price-analyzer>
- Documentation site: <https://napstablook666.github.io/ai-price-analyzer/> (VitePress; the plugin protocol lives under "Plugin development")
- Full protocol documentation on the extension side: [docs/plugin-development.md](https://github.com/napstablook666/ai-price-analyzer/blob/main/docs/plugin-development.md)
- Plugin repository development guide: [DEVELOPMENT.md](./DEVELOPMENT.md)

## Directory layout

```text
ai-price-analyzer-plugins/
  <id>/
    manifest.json   # site metadata for display and host matching
    plugin.js       # export const sitePlugin
    models.json     # optional aliases from station model names to canonical model ids
  README.md
  DEVELOPMENT.md
```

A plugin id must satisfy all of the following:

- The directory name, the `id` in `manifest.json`, and `sitePlugin.id` in `plugin.js` are identical.
- Lowercase letters, digits, and hyphens only.
- No station secrets, cookies, tokens, Authorization headers, private URLs, or full private responses.

## Relationship with the extension repository

The plugin and extension repositories are two independent Git repositories. The common layout checks this repository out as `plugins/` at the extension repository root:

```text
ai-price-analyzer/
  extension/
  scripts/
  docs/
  plugins/          # nested checkout of this repository, an independent Git repo
```

The extension repository does not track the plugin sources here. It generates the runtime plugin files into:

```text
extension/src/site-plugins/providers/<id>.js
extension/src/site-plugins/catalog.js
extension/src/shared/plugin-order.js
```

The generated files are committed to the extension repository, so a plain extension checkout loads directly; plugin source changes must still be regenerated. Never edit the generated files by hand.

## Plugin store (plugins.json)

`plugins.json` is the published plugin manifest of this repository. The extension reads it by default from:

```text
https://raw.githubusercontent.com/napstablook666/ai-price-analyzer-plugins/main/plugins.json
```

The extension's "Sites & plugins → Plugin repository" page accepts any URL serving the same structure. Manifest structure:

```json
{
  "schemaVersion": 1,
  "plugins": [
    {
      "id": "windhub",
      "name": "WindHub",
      "version": "0.2.1",
      "description": "Public pricing endpoint of a free public station",
      "hosts": ["windhub.cc"],
      "needsCode": true
    }
  ]
}
```

`needsCode: true` means the plugin depends on collection code in this repository's `plugin.js` and must wait for an extension release; `false` means the plugin can be a declarative spec (`hosts` / `paths` / `request` / `responseFormat` / `preset` fields, no injected code) that the extension installs straight from the manifest.

This manifest is generated by `node scripts/plugin-build.mjs` in the extension repository. Do not edit it by hand.

## Loading local plugins in development mode

After enabling "Development mode" in the extension settings, you can paste or pick a plugin JSON spec to load directly. It only takes effect on this machine and is marked as a "Local plugin" in the installed list. Turning development mode off uninstalls local plugins along with it.

A local plugin spec is the same field set as a declarative plugin:

```json
{
  "id": "my-site",
  "version": "0.1.0",
  "name": "My Site",
  "hosts": ["pricing.example.com"],
  "paths": ["/api/pricing"],
  "request": { "endpoint": "/api/pricing", "credentials": "omit" },
  "responseFormat": "auto",
  "category": "paid",
  "mode": "direct"
}
```

`responseFormat` only works with price formats the extension already supports; custom parsing logic requires a PR to the extension repository.

## Quick start

### 1. Prepare both repositories

```bash
git clone https://github.com/napstablook666/ai-price-analyzer.git
cd ai-price-analyzer
git clone https://github.com/napstablook666/ai-price-analyzer-plugins.git plugins
```

The plugin repository can also be checked out elsewhere; point `PLUGIN_DIR` at it.

### 2. Modify a plugin

Edit only:

```text
<id>/manifest.json
<id>/plugin.js
<id>/models.json
```

### 3. Generate and verify from the extension repository

Run these commands from the extension repository root, not inside the plugin repository:

```bash
node scripts/plugin-build.mjs
node scripts/plugin-build.mjs --check
npm test
```

When the plugin repository lives outside the extension repository:

```bash
PLUGIN_DIR=/path/to/plugins node scripts/plugin-build.mjs
PLUGIN_DIR=/path/to/plugins node scripts/plugin-build.mjs --check
```

Windows PowerShell:

```powershell
$env:PLUGIN_DIR = 'C:\path\to\plugins'
node scripts/plugin-build.mjs
node scripts/plugin-build.mjs --check
```

## Pre-commit checklist

- `manifest.json` has no unknown fields, and the site id matches the directory name.
- `plugin.js` exports `sitePlugin` and only uses static imports from `@app/core/...` or `@app/shared/...`.
- No dynamic `import()`, no DOM access, no `../../` imports.
- Add station-specific model aliases to `models.json` only when truly necessary.
- Run `node scripts/plugin-build.mjs --check` and `npm test` from the extension repository.
- After manually verifying a real collection run, commit the plugin repository sources and the extension repository generated files separately.

For the full field reference, request policies, model alias precedence, same-host path constraints, and manual acceptance steps, see [DEVELOPMENT.md](./DEVELOPMENT.md).
